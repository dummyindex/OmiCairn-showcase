Platform

The OmiCairn platform

OmiCairn’s first version, code name Stoneflow, was a workflow-based web platform for omics analysis, in the spirit of Galaxy or Nextflow. It is now Fully Deprecated and Retired, and no longer in production. Its node-based, flow-style interface has been replaced by OmiCairn’s chat-based interface, which is in production. Users dragged datasets and function blocks onto a canvas, joined them into an analysis tree, ran every node in its own container, and inspected the results in a visualization panel with an AI assistant at hand. The analysis tree of function blocks is still its core. What later versions added is accountability: pre-registered plans, deterministic cross-checks, a claim-review agent and reviewer agents.

Lineage

Four stages, one unit of work

Each stage kept the analysis tree of containerized function blocks and changed who drives it: a person at a canvas, then agents on one machine, then agents on a hosted platform, then a pipeline that has to justify every claim it makes.

    OmiCairn

    A question goes in, not a pipeline. Agents scope the question, pre-register the analysis plan and decision rules, execute it, cross-check every reported number against the code that produced it, and review whether the evidence answers the question.

The unit that carried over

  1. Function blockCode (Python, R or shell), its dependencies and container image, typed arguments, documentation
  2. instantiate
  3. NodeThe block with parameters and configuration, run in its own container, with results and logs
  4. compose
  5. Analysis treeNodes joined by data dependencies; each node can be inspected, rerun or extended

First version

  • Analysis trees of function blocks, each block instantiated as a node.
  • Containerized execution, with code, parameters, logs and outputs kept per node.
  • Interactive visualization of results in a visual panel.
  • A person drives: builds the tree, sets parameters, decides what runs next.
  • Assisted debugging of failed nodes.

Today

  • A question as input; agents scope it and plan the tree.
  • Pre-registration of hypotheses and decision rules before any analysis runs.
  • Deterministic cross-check: every reported number resolves to executed outputs.
  • A claim-review agent and reviewer agents check the report against the evidence.
  • Experience replay of validated blocks and fixes; experts can still steer.

01

Build the analysis tree

Datasets and function blocks are dragged onto a canvas and wired together. Each connected block becomes a node that runs on its own, and the whole graph is the analysis tree.

02

Inspect results visually

Any completed node opens in a visualization panel built for single-cell and spatial data: embeddings, cell metadata, gene lists, cell sets and annotations.

03

Work with the assistant

A language-model assistant sat beside the canvas. It explained results, diagnosed failed nodes, and filled in parameters. The user decided what to run.

04

Manage data

Public datasets could be imported in a click; users’ own data came in as AnnData, 10x outputs, component matrices or Space Ranger folders.
